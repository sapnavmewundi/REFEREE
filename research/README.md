# REFEREE Research Dataset & Reproduction

This directory makes every number in the talk/paper reproducible: point
`analyze.py` at the raw DeepScan JSON reports and it regenerates the funnel,
the category-risk chart, the gap matrix, and the summary table deterministically.

## Reproduce

```bash
# From one or more DeepScan JSON reports (per host):
python3 analyze.py --reports ../auditor/out --out ./figures

# Or explicit files:
python3 analyze.py --reports host-a.json host-b.json --out ./figures
```

Outputs land in `figures/`:

| File | What |
|------|------|
| `reachability_funnel.csv/.png` | total drivers -> flagged -> user-reachable -> LOW-tier |
| `category_risk.csv/.png` | avg three-axis score + reachable count per driver category |
| `axis_breakdown.csv` | every flagged driver with its per-axis scores (the full dataset) |
| `gap_matrix.csv` | capability x catalog quadrant counts |
| `summary.md` | headline numbers for the slides |

`matplotlib` is optional — CSV + Markdown always generate; PNGs need
`pip install matplotlib`.

## Dataset schema (DeepScan JSON)

Each per-host report is one JSON object:

```jsonc
{
  "tool": "referee-deepscan",
  "host": "DR_SAPNA",
  "generated": "2026-11-09T...",
  "os": "Microsoft Windows NT 10.0...",
  "total_drivers": 482,          // all kernel drivers enumerated
  "flagged": 309,                // drivers with any risk signal
  "stats": {
    "critical": 2, "high": 7, "medium": 40, "low": 260,
    "user_reachable": 24,        // openable from an unprivileged process
    "restricted": 180,           // admin/SYSTEM only
    "reach_low_tier": 6,         // openable even from a sandbox/AppContainer
    "reach_medium_tier": 18,     // openable from a standard-user token
    "wdac_blocked": 9            // targeted by the generated block policy
  },
  "category_breakdown": [ { "Category","Count","AvgScore","UserReachable" } ],
  "findings": [ {
    "driver": "vgk.sys", "category": "Anti-Cheat",
    "cap_score": 25, "cat_A": "...", "cat_B": "...", "cat_C": "...",
    "reach_score": 32, "acl_status": "USER_REACHABLE",
    "reach_tier": "MEDIUM", "reach_principal": "BUILTIN\\Users",
    "vuln_score": 20, "lol_match": false, "lol_hash": "N/A",
    "total_score": 77, "exposure_score": 6, "risk_level": "CRITICAL",
    "signature": "Valid", "signer": "CN=Riot Games...",
    "file_hash": "<sha256>", "path": "C:\\Windows\\System32\\drivers\\vgk.sys"
  } ]
}
```

## The three axes (how a driver is scored)

1. **Capability** (0–30) — which dangerous kernel-API classes the PE imports:
   A = physical/virtual memory mapping, B = cross-process access, C = defensive
   callback removal.
2. **Reachability** (0–40) — can an unprivileged process open a handle? Depth
   matters: LOW tier (sandbox/AppContainer-reachable) scores above MEDIUM
   (standard-user-reachable). This axis is the research contribution.
3. **Known vulnerability** (0–30) — loldrivers.io cross-reference with SHA256
   hash verification (EXACT_HASH vs NAME_ONLY).

`exposure_score` (0–9) is a separate prioritization metric: breadth of
capability classes × reachability multiplier. It answers "fix this first,"
not "exploit this."

## Ethics

All reports are generated by read-only scans on machines we own. Before
publishing the dataset, host identifiers are anonymized and no undisclosed
vendor-specific vulnerability detail is included (see `../disclosure/CVD_POLICY.md`).
